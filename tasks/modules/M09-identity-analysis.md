# M09：只读身份分析

## 目标

在既有四层工程中呈现身份配置声明、客户机观测及可信度，作为 v0.3 的首个开发模块。入口：[计划](../../docs/V03-PLAN.md)、[M08 结论](../../docs/V03-M08-FEASIBILITY.md)。

## 前置条件

M08 已完成；后续任务明确开启本模块。遵守既有版本/维护策略，不新增驱动、框架或系统服务。新采集与报告格式变动先核实现有接口和兼容约束。

## 具体子任务

- 优先复用现有 14 项实际采集，分列配置声明与实际观测，保留来源、时间和状态。
- 设计敏感标识的最小采集和本地对照；默认不新增原始 MAC、UUID、序列号采集/导出，用户明确选择后才执行新增采集。
- 为新增字段确定真实只读来源及超时/权限/不支持语义；目录中的三个 Identifier 定义不能算采集完成。
- 对比结果区分相同、不同、状态不同、不可比较；脱敏后的掩码不用于判断真实标识相等。
- 在既有 WPF 页面加入能力与依据说明，保持双语、后台采集及取消。

## 实施步骤

1. 先审查报告版本、隐私和导入规则，按真实需要扩展模型；无必要不升级格式。
2. 用合成数据验证状态、来源及隐私，再实现受支持的只读采集。
3. 接入已有 UI/CLI 与报告对比；用新旧报告验证兼容。
4. 更新报告说明、用户指南、结果与日志；实际 VM 测试按后续具体范围执行。

## 自动化测试

验证旧报告兼容、敏感值默认排除、显式采集选择、读取失败/超时/取消和不可比较语义；HTML 继续编码不可信值。仅运行受影响测试，开发和模拟测试不开 VM。

## 验收标准

- [x] 配置声明、客户机/本机报告观测、能力状态和依据分开显示；未确认来自同一VM。
- [x] 新增字段有实际来源及故障状态；缺失不伪装成成功。
- [x] 旧报告仍可读取；新报告默认脱敏，未选择时不采集新增原始标识。
- [x] UI/CLI 共用采集引擎，耗时操作可取消且不冻结 UI；本机GUI实际取消通过。
- [x] 相关测试通过，普通权限真实读取结果另列，不挪用 v0.2 结果。

## 风险与回滚方案

标识可能敏感，读取能力也可能因系统版本不同而缺失。优先减少采集；新增字段保持可选、未知可展示。通过独立本地提交回退代码/格式扩展，保留旧报告，不覆盖用户文件。
