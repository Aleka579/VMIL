# M13：v0.3 验收与交付

## 目标

按实际完成范围交付可追溯的 v0.3 源码、双语说明、测试证据及 Windows 包。未通过准入的写入项继续禁用并明确说明。入口：[v0.3 计划](../../docs/V03-PLAN.md)。

## 前置条件

M09–M12 中拟交付内容完成且限制明确；没有合格写入项时，先明确是否以只读分析范围交付。M08 完成不代表本模块完成；版本更新、推送和 Release 不由本计划自动授权。

## 具体子任务

- 更新 README、使用指南、报告格式、兼容性、变更记录、安全边界及发布就绪表。
- 沿用 MIT / Daniel Waltz 与私密安全渠道，核对实际依赖和第三方许可，不捆绑 VMware/Windows/真实 VM 数据。
- 发布前复核工具维护期，不新增临近停止支持的工具；既有用户例外不自动扩大。
- 从明确提交构建固定版本包，记录 SDK、Runtime、文件清单和 SHA-256。
- 在授权后运行真实 GitHub CI，验收最终 CI 原始字节包，不用旧 v0.2 结果代替。

## 实施步骤

1. 固定拟交付范围、版本与来源；先完成本地受影响测试和脱敏检查。
2. 整理具体待上传源码差异并按规则确认远程操作；不得直接上传含私有日志的内部历史。
3. 核实 CI 实际日志及最终包，在明确 Windows 目标完成普通权限验收。
4. 完成 RELEASE-READINESS.md 的本版状态，准备具体 Release 资产/说明，获授权后发布并核对服务器哈希。

## 自动化测试

执行与新增实现相称的单元/模拟集成、Release 构建和实际 CI；最终包做结构、版本、敏感数据和许可检查。真实 VM/干净目标验证单列，不以工作流静态检查冒充云端通过。

## 验收标准

- [x] 拟发布范围、支持/不支持字段及未验证环境清晰且与 App 一致。
- [x] 受影响自动化测试和真实 CI 通过，失败历史可追溯。
- [x] 最终版本原始包通过声明目标验收；来源、版本及哈希一致。
- [x] 双语文档、许可证、安全声明和敏感数据检查完整。
- [x] 发布前完成具体授权；发布后核对资产和回执，不改写旧包/tag。

## 风险与回滚方案

CI 包与本地包可能不同，必须记录独立来源和验收。发现缺口则暂缓发布并保留失败证据；不移动已有标签或覆盖历史资产。远程撤回或后续修订按具体问题和授权处理。
