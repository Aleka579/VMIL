# M12：身份变更验证闭环

## 目标

区分配置是否写入、客户机是否观测到变化、自有或获授权测试程序行为是否变化，以及恢复是否完整。入口：[v0.3 计划](../../docs/V03-PLAN.md)。

## 前置条件

M09 可读取和比较证据；写入实验依赖 M11 对应候选、具体授权和独立副本。若只交付只读范围，本模块明确仅验收分析功能，不伪造写入闭环完成。

## 具体子任务

- 明确自有或获授权的目标程序和期望行为，不测试反作弊/反欺诈/授权规避。
- 当前目标固定为VMIL自有证据分类器；三阶段使用同一会话，配置记录、Windows原值对照及当前程序对导入观测的分类分层，不使用综合去虚拟化分数。
- 保存变更前、变更后和恢复后三组来源清楚、默认脱敏的结果。
- 使用独立 Windows/VMware 观测对照，不能仅依赖 App 自己的写入返回值。
- 检查其他字段保留、启动/网卡状态、普通权限与双语界面。当前已准入范围要求网卡断开，核实正常启动、Tools及实际断开状态；联网连通性保持未验证，需要新的联网准入和具体方案，不能以Tools正常替代联网测试。
- 保存失败、部分成功和未执行项；检测器分类改变只作为特定程序的观测。

## 实施步骤

1. 在模拟数据上验证报告对比与缺失/不可比较语义。
2. 准备具体真实验收方案和证据位置，获得必要授权后才进入副本实验。
3. 逐字段验证，不混合多项修改掩盖失败原因；执行恢复后独立复核。
4. 按约定结束状态和清理范围收尾；删除副本前核实实际绝对路径与引用独立性。

## 自动化测试

覆盖三组报告比较、来源不一致、脱敏后不可比较、部分失败和旧格式兼容。真实验证可用已有本机工具记录，不新增常驻代理、驱动或测试框架依赖。

## 验收标准

- [x] 每项通过结论对应版本、字段、值及变更前/后/恢复后证据（e0f4e10新包六份真实快照150/150、四次正常App预览32/32、收据36/36及独立CIM/API对照；原值仅私有保存）。
- [x] 配置结果、客户机观测与程序行为三者独立呈现（普通App合成三阶段、23项检查/3条程序观测及脱敏JSON/HTML）。
- [x] 失败/未知保持原始状态，不降低阈值或删除失败记录（缺失/脱敏/来源/版本/会话/时序/采集状态、错误恢复及输入拒绝覆盖通过）。
- [x] 普通权限、隐私和实际 App 流程通过；未测试环境明确列出（宿主及Win10教育版Build18363/X64客户机真实双语/脱敏各34/34，已有导出不覆盖、App退出通过；其他环境、联网和最终CI包未验证）。
- [x] 副本与临时凭据按具体授权清理，原 VM 保持用户指定状态（原VM独立API确认挂起、关键配置保留；637份最后GUI后元数据归档，唯一副本API/库树/持久清单0且目录删除，临时凭据及自有API进程已结束）。

## 风险与回滚方案

真实程序行为可能不变，结果须如实记录。恢复受 M11 同等保护；若失败则停止并保留证据与恢复入口，不覆盖用户后续修改。任何安全产品拦截立即按 AGENTS.md 停止规则处理。
