# 阶段 1：只读系统检测与报告模型

- 版本范围：v0.1。
- 当前状态：实现/适用自动化/真实宿主与Win10客户机采集通过。
- 验收进度：5/5；证据索引见 PROGRESS.md 与 WORK_LOG.md。
- 全局入口：[PLAN.md](../PLAN.md)、[WORK_LOG.md](../WORK_LOG.md)、[PROGRESS.md](PROGRESS.md)。

## 目标

形成可解释、可降级、默认脱敏的 Windows 系统特征采集引擎。

## 前置条件

- 宿主机实际 API/工具兼容性可核实，不设 OS 版本/支持期门槛；.NET 10 LTS 受维护 SDK 可用，客户机准入仍需核实。
- docs/REPORT-SCHEMA.md 中的数据状态和隐私规则已确认。

## 具体子任务与实施步骤

- [ ] 定义结构化报告、采集项、采集状态、证据来源和虚拟化解释模型。
- [ ] 实现 SMBIOS、CPU、PnP 设备、VMware Tools、系统信息五类采集；优先使用 Windows 平台 API。
- [ ] 每类采集独立处理失败、超时和权限不足，不把失败转成成功的空结果。
- [ ] 分别呈现 Hypervisor 信号、VMware 客户机证据和相关软件痕迹；不根据单个信号断定物理机或客户机。
- [ ] 统一脱敏路径、用户信息、序列号、UUID、MAC 等字段；公开报告保留有诊断意义的型号、类型和功能信息。
- [ ] 实现命令行采集入口并共享同一采集引擎；报告写入用户指定位置。

## 自动化测试与人工验证

- 使用合成采集结果验证各类状态、异常和证据解释。
- 覆盖 Hyper-V 宿主机、VMware 客户机证据、Tools 痕迹、无相关信号和数据不可用场景。
- 验证 JSON 可解析、格式版本正确、默认不含敏感字段；硬件接口调用失败仍能输出部分报告。

通用记录模板与测试类别见 [TEST-PLAN.md](../docs/TEST-PLAN.md)。模拟、临时文件、UI、真实 VM、干净环境与远程 CI 结果分开记录。
