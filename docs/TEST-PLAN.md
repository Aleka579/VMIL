## 重点场景

- Hyper-V 宿主机：有 Hypervisor 信号也不单独断定 VMware 客体。
- VMware 客体：多来源证据一致；Tools 痕迹不作为唯一依据。
- 硬件接口无权限、不可用、超时或异常：保留分项状态与其他结果。
- VMX 编码、注释、换行、未知参数、重复键和损坏输入：零修改字节一致，可写歧义明确拒绝。
- 四电源状态、查询失败、占用、预览后外部变化：旧预览不能用于新内容。
- 新建临时文件中的写入、替换、验证与恢复失败：保留恢复入口，不操作用户 VMX 做故障注入。
- 合成用户名、路径、序列号、UUID、MAC、敏感配置和 HTML 标记：默认日志/报告无原值、HTML 正确编码。
- 对比中的不同单位、状态、缺失和脱敏字段：不伪造实际硬件变化。
- 已安装 SDK 的开发机成功：不能代替普通用户/干净环境启动验证。
- 用户指定Windows/VMware按明确例外进行项目兼容测试，官方支持另列；其他SDK/脚本/依赖/CI临期、维护未知或弃用时记录缺口，不以一次成功冒充上游支持。

## 记录模板

每次实际执行保存：证据编号、验收编号、日期时间及时区、应用/提交版本、运行目录、环境、命令或人工步骤、授权范围、预期、实际结果、通过/失败/未验证、失败原因、修复、文件入口和下一步。

私有原始结果建议放 local-data/test-results/。项目日志记录脱敏摘要和证据入口；公开证据用合成示例或用户同意且已审查的脱敏结果。

## 计划命令（源码创建后执行）

源码和解决方案已建立。下列标准命令使用符合 global.json 的 SDK；本机当前使用 artifacts/tooling/dotnet/dotnet.exe。实际结果见 WORK_LOG.md，不能把计划命令当作已执行。

```powershell
dotnet restore VMIdentityLab.sln
dotnet build VMIdentityLab.sln -c Release -m:1 --disable-build-servers
dotnet test --project tests/VMIdentityLab.UnitTests/VMIdentityLab.UnitTests.csproj -c Release --parallel none
dotnet publish src/VMIdentityLab.App/VMIdentityLab.App.csproj -c Release -r win-x64 --self-contained true -o artifacts/publish/win-x64
```

集成测试命令在实现时按类别明确区分临时文件和真实 VM。默认 CI 只运行获定义的非破坏性类别，不能通过一个总命令自动操作真实 VM。

.NET 10/MTP 测试参数不使用旧 SDK 的 -- 分隔方式。开发验证设置 DOTNET_CLI_TELEMETRY_OPTOUT=1 和 TESTINGPLATFORM_TELEMETRY_OPTOUT=1；测试结果文件放在忽略的 artifacts/test-results/，文件名不包含个人标识。
