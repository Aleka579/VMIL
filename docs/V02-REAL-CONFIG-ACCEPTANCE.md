## 先解决的技术条件

1. 确定目标 Workstation 版本的配置更新方式、允许值与 CPU 拓扑约束。随附 Swagger 与[官方更新接口](https://developer.broadcom.com/xapis/vmware-workstation-pro-api/latest/api/vms/id/put/)有更新及状态冲突定义，但没有证明当前 VMX 文件替换与启动/外部替换互斥。
2. 按[写入设计](CONFIGURATION-WRITE-DESIGN.md)完成可测试的保护。若采用 VMware 管理接口，需要目标版本实际拒绝运行/挂起/未知状态以及并发状态变化的证据；若继续文件替换，需要证明其互斥条件。不能用更快查询或 FixturePolicy 替代。
3. 保持发布策略拒绝，先完成实现与适用模拟/文件测试，再准备具体真实操作。当前 App 的禁用确认按钮意味着不能执行真实应用/恢复验收；一次复制或用户授权也不能补足代码保护。

## 已准备的副本方案

2026-10-14只读预检观察到源目录一块约57.1 GiB VMDK，描述符为无父盘提示的基盘，快照元数据为空；源目录当时约63.1 GiB，包含运行时内存文件。目的地不存在，D可用约176.2 GiB。精确路径、哈希与数据在私有 `local-data/test-results/v02-acceptance-20261014-162000/copy-preflight.json` 和 `REAL-VM-ACCEPTANCE-PLAN.md`，不进入公开文档。

完整复制前重新查询可靠的完全关机状态、源清单、所有盘/父盘/外部引用和空间；运行中预检不能代替。预留70 GiB用于副本及测试增长，原 VM 需要正常软关机期间的短暂中断。完整副本存放项目私有目录，测试结束保留，删除单独处理。

[Broadcom 复制流程](https://knowledge.broadcom.com/external/article?legacyId=2030609)要求先关机，并说明运行/挂起期间复制可能无法启动；该文章的环境列表截至16.x，仅作为关机/完整复制前提，目标17.5.2的具体实现仍须验证。

## 取得具体授权后的验收顺序

| 操作 | 验证与恢复要求 |
| --- | --- |
| 源 VM 正常软关机、完整复制 | 用户先保存客户机工作；确认可靠 PoweredOff。使用新目的地、不覆盖数据、不只复制 VMX，不强制断电或删除锁文件 |
| 副本独立性核实 | 逐项解析所有磁盘/父盘/外部写资源引用，均独立于原 VM。无法确认则不启动、不配置 |
| 原 VM 恢复原运行状态 | 正常启动，核对原配置；复制失败保留现场，不修改原磁盘/快照 |
| 副本候选差异 | 仅评估内存6144→4096 MiB、vCPU4→2，coresPerSocket保持2；这只是待验证候选，不是已批准范围 |
| 副本应用、启动检查、软关机后恢复 | 每次具体操作处于授权范围；先备份原字节，确认新差异/状态/版本，验证客户机实际资源和恢复记录。真实失败保留备份和证据，不盲目回写 |
| 拒绝与失败场景 | 运行/挂起/未知/占用/外部修改/并发启动等按已实现保护验证；破坏性故障先在临时文件验证，不用原 VM 模拟 |
| 发布白名单与CFG验收 | 官方目标版本依据、真实副本、应用/恢复与保护证据齐备后逐项审查；不可用单次成功或空白名单补勾 |

项目[AGENTS.md](../AGENTS.md)的“授权”规定：完整 VM 副本、真实配置写入与电源/快照操作必须在具体方案后确认。本轮只做预检和计划，没有执行这些操作。下一项开发工作是上述保护与依据，真实操作授权在方案可执行时取得。
