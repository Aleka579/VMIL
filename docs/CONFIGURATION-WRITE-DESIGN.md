# v0.2 配置提交与恢复设计

2026-10-16更新。本文件记录生产代码与放行条件，不授权真实VM操作。最新实现、测试及证据见[API后端结果](V02-API-BACKEND-2026-10-16.md)。

## 生产路径

WPF保留不可变预览、唯一确认ID、逐项差异和影响说明。输入、目标、恢复记录或状态变化使旧预览失效。确认之后通过`VmxConfigWorkflow`调用`VmxApiConfigManager`，由官方`PUT /api/vms/{id}`提交本次改变的`memory`/`processors`，不回落到直接替换VMX。CLI仍只读，不自动启动vmrest或操作VM电源。

`WorkstationRestClient`复用清单、状态、设置读取和有限字段更新。目标须在本机API清单中唯一对应完整VMX路径；设置响应须有相同ID和无歧义的正整数。使用请求级凭据，禁止重定向和代理，响应大小、JSON深度与完整读取时间受限，不回显厂商错误正文，不自动重试。

`ReleasedVmxApiWritePolicy`独立于仍关闭的旧文件策略，只批准已实测登记版本17.5.2.23775571、hardware19、每插槽2核、4096↔6144MiB和2↔4vCPU；缺失/其他构建号、数值或拓扑均拒绝，没有环境变量/命令行放行开关。真实运行/挂起409及一次启动竞争已验证；立即状态读取可能滞后，提交后完整状态/哈希复核不放宽，内容变化保留未决结果。见[本轮证据](V02-FULL-TEST-RESULTS-2026-10-17.md)。

## 提交与并发保护

1. 验证当前确认ID、候选/发布策略、实际安装版本、完全限定的本地路径、语法及拓扑；不接受重解析路径或只读目标。
2. 对目标同目录的`.vmidentitylab-api.lease`保持`FileShare.None`句柄，直到本次事务结束。相同目标的其他App实例/进程不能同时进入；不同目标互不串行阻塞。租约文件保留，不能通过删除文件解除活动操作。
3. 发现`.vmidentitylab-api.pending.json`文件或目录即拒绝新提交，包括损坏或无法解析的记录；不猜测上次是否成功。
4. 重新映射API目标，核实新鲜可靠完全关机证据；独占读取当前VMX，核对预览原始哈希和API内存/CPU一致性。
5. 用`CreateNew`写入原字节备份与预期配置暂存文件，刷盘后重读验证。再核实映射、状态、API设置、版本、路径和原始哈希，外部变化使预览失效。
6. 请求发出前持久化并重读核对intent，包含操作ID、后端、时间、目标/备份/暂存路径、哈希和版本，不含凭据。
7. 检查请求前取消；之后仅发送一次PUT。发出后的用户取消不代表服务端未修改，后续受API时限约束地继续核实结果。
8. 核实响应、重新读取的设置、目标映射、关机状态、版本及完整VMX预期哈希。全部一致才归档`completed`并生成收据。

租约是App实例间的协作互斥；短暂的VMX独占读取、内容哈希和多次状态检查是冲突检测。它们不能锁住不遵守租约的外部编辑器、VMware启动或路径更换。真实VMware状态约束依赖provider行为，不能用本地模拟结果宣称全局互斥。[FileShare.None契约](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileshare?view=net-10.0)只支持本地句柄约束；[官方更新接口](https://developer.broadcom.com/xapis/vmware-workstation-pro-api/latest/api/vms/id/put/)列出409冲突，但没有定义本项目所需的CAS、幂等键或完整并发保证。

## 结果未确认与失败

超时、断线、异常/错误目标响应、部分变更、提交期间启动或外部变化均保留pending、原字节备份和预期配置。新实例或重启后仍阻止重放；App显示未决提示及证据位置，不自动重试、删除记录或回滚。当前没有自动核销未决记录功能：必须先证明服务端操作已经结束，再核实实际配置，不能仅因当前字节暂时未变就解除阻止。

对已完成的400/401/403/404/406/409响应，只有额外确认目标ID、API设置和原始内容均未变，才归档`rejected`；下一次仍须重新读取和明确确认。请求前取消可归档`not-sent`。验证/归档失败保留现场；任何请求结果未明都不能按“失败所以没有变更”处理。

旧`VmxConfigManager`保留合成文件事务测试和历史只读恢复预览，不被App用作写入后端；旧文件策略也未开放。最后窗口替换保全修复及真实原生API候选往返保留在[此前验收](V02-CONFIG-ACCEPTANCE-2026-10-16.md)，不追改为本次生产路径证据。

## 历史与恢复

成功收据使用私有历史schema2，记录后端、内存/CPU/拓扑/硬件前后值、目标/备份路径及哈希。schema1仍按旧文件后端读取；未知版本、后端伪装或损坏记录保留并提示。完成后的操作journal也保留证据；进程在历史保存前退出时不会自动导入它。

API恢复验证备份原始哈希、所选目标和收据拓扑；当前候选值必须等于收据应用后的值。只为本次改变的内存/CPU生成反向预览，以最新完整内容为基准，保留启动后更新的其他VMware字段。候选或拓扑被后续改变时拒绝；不将旧完整备份覆盖当前VMX。恢复同样经过新确认、发布策略和API事务，并备份当前字节。

配置已完成但历史保存失败时，保留收据和备份入口，阻止再次应用；只允许重试保存历史，不重发PUT。配置备份不恢复磁盘、客户机、快照或整机状态。
