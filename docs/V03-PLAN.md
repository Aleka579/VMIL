## 1. 最终交付目标

让用户看到虚拟机暴露了哪些身份信息、哪些有官方配置途径、当前版本实际支持哪些操作，以及变更在客户机中是否生效。对于未来获准的字段，提供逐项预览、确认、备份、应用、复测和受控恢复。

v0.3 不承诺“所有软件都认为是物理机”。修改 MAC 或 UUID 不会自动改变 CPU、固件、设备、驱动和软件等其他证据；配置写入成功、客户机观测改变、目标测试程序分类改变，是三个分别记录的结果。某个程序的分类变化不能证明环境已成为非虚拟环境。

适用场景是自有或获得明确授权的兼容性测试、克隆后的身份唯一性检查、报告对比和教学。不可验证的项目显示“未知”或“当前不支持”，不能用推测填充成功状态。

## 4. 分阶段实施门槛

1. **G0：可行性审查。** 区分本机安装版本、在线 API 文档版本、历史 KB 范围、当前 App 能力和真实测试。M08 已完成，见报告。
2. **G1：只读分析。** M09 先覆盖现有真实采集项、配置声明和故障状态；新增敏感标识必须先完成采集必要性及隐私设计。新旧报告均可导入，未知字段和未执行项不能变成成功。
3. **G2：离线预览。** M10 只能生成带依据的计划，注明目标版本、值约束、风险、恢复范围和实测缺口。原始物理机标识不导入为冒充模板。
4. **G3：字段准入。** 每个字段必须有适用版本的官方依据、明确允许值、可用官方通道、状态/并发语义及可验证恢复方案。通用参数接口存在不满足逐字段准入。
5. **G4：独立副本实验。** 另行准备目标、差异、资源影响及恢复方案，经用户具体授权后才创建完整副本、操作电源或写入。核实磁盘与快照链独立；按值与版本保存往返证据。
6. **G5：生产闭环。** 复用 M07 的状态、预览失效、租约、备份、持久化未决记录和防重放；通过 App 应用/重开/恢复及独立观测。无生产 VMX 直接写入回落。
7. **G6：版本交付。** 运行适用自动化测试和真实 CI，对最终包进行声明环境的普通权限验收；源提交、版本、哈希及实际范围可追溯。远程推送、标签和 Release 仍按具体内容确认。

本轮止于 G0，不因计划中出现后续步骤而获得操作授权。

## 5. 四层职责与界面结果

- **Core**：能力状态、证据等级、身份差异、报告兼容及隐私规则；不依赖 VMware 或 WPF。
- **Windows**：普通权限只读观测，保留来源、超时和不支持状态；不拦截系统查询、不注入目标进程。
- **VMware**：配置声明、版本匹配、官方后端能力及已获准事务；未知字段保持只读。
- **App**：在既有页面中呈现身份分析、实验计划、差异和恢复结果；后台执行耗时工作，中文/英文资源一致。

每个身份项分别展示“配置声明”“客户机观测”“依据与适用版本”“当前能否修改”“验证状态”。不能把有配置名称、字段目录或接口返回值误标为采集成功或可修改。M08 发现目录中的三个敏感标识定义尚不等于当前采集器已输出，详见调研报告。

## 6. 数据、备份与恢复

- 默认不新增采集或导出 UUID、MAC、序列号原值；确需本地对照时再设计最小保留和明确选择，导出继续默认脱敏。不使用无盐哈希承诺标识匿名化。
- 报告继续区分不可见、未采集、失败与实际相同/不同。若脱敏导致不能可靠比较，应明确不可比较；不凭掩码推断相等。
- 不将自有物理机真实标识复制到配置档案，不在 Git、公开样例或日志保存真实 VM 数据和凭据。
- 备份必须覆盖该字段实际改变的资源及关联状态。VMX 字节备份不是整机备份，也不能假定足以恢复 NVRAM、磁盘或客户机配置。
- 恢复条件与应用同样严格；有外部后续修改或结果未知时，不覆盖、不盲重试。不能证明恢复完整的字段保持只读。
- 不删除锁文件、挂起文件或快照，不改虚拟磁盘内容，不移除 TPM，不自动重置固件或磁盘身份。
