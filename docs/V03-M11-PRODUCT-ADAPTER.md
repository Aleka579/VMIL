## 实现范围

| 部分 | 行为 |
| --- | --- |
| 候选 | `IdentityConfigField.StaticMac` / `BiosUuid`，一次一个字段；系统随机数生成 VMware 格式新值，不接受自定义标识、物理机模板或任意键值 |
| 输入 | 明确的 hardware19、有效已有 VMware 静态 MAC/BIOS UUID、单个 static/hostonly 网卡且 `startConnected=FALSE`；自动地址、多网卡、缺失键、加密或歧义输入拒绝 |
| 版本 | 候选事务内部限定完整版本 `17.5.2.23775571`；版本未知或其他构建不因注入测试策略而获准 |
| 通道 | 复用 `VmxApiConfigManager`；封闭适配 `PUT /api/vms/{id}/params`、字符串 name/value、厂商媒体类型，以及实测空 200 成功响应 |
| 保护 | 当前确认 ID、唯一注册映射、完全关机、两标识与 VMX 一致、原内容、路径及占用检查；验证备份/预期配置/intent 后再次检查，随后最多发送一次 PUT |
| 复核 | 独立重新映射、读取状态和两标识，核实完整配置键值、独立及行尾注释；只容许换行、条目顺序等无语义格式差异，收据保存实际观察字节的哈希 |
| 未决 | 超时、响应无效、未生效、其他字段或注释变化、运行状态变化等保留 pending、原始备份和预期配置，阻止再次写入，不自动回滚或核销 |
| 恢复 | 私有 schema3 收据保存前后身份及相关配置摘要；重开历史后验证备份原始字节、两标识和相关配置，以最新完整文件生成单键逆向预览，保留后来的无关配置 |

依据来自[精确构建的真实研究复验](V03-M11-REAL-API-RETEST.md)；本轮没有把研究工具直接当作生产 App 后端，也没有扩大该研究结论。既有数值策略不变，仍严格检查预期完整字节。旧文件后端即使注入测试审批策略，也拒绝身份计划；没有 API 失败后直接改 VMX 的回落。

M10 的 MAC 唯一性意图和 UUID 复制生命周期模型、未执行状态及报告 schema 均不变。本轮是替换**已经存在的字段**，不实现厂商自动生成、复制或缺失键删除/恢复；随机值不保证跨 VM 唯一，也不改变其他虚拟化证据。

## 界面与私有数据

配置页面新增封闭候选选择和“生成新值并预览”，与原内存/CPU候选共用差异及审阅流程。默认隐藏标识值；确认窗口需显式勾选才在本机显示，显示不会改变提交权限。切换候选、改变目标或输入检查失败会清除旧预览。

`ReleasedVmxApiWritePolicy` 没有新增批准项，因此正常 App 的身份确认和提交保持禁用，不打开连接凭据窗口。没有命令行、环境变量或报告导入放行开关。模拟测试只在临时合成文件中使用既有策略注入点。

身份备份/历史包含原值，属于私有恢复数据，不能随诊断或发布包分发。数值历史继续保存 schema2，且不添加 null 身份属性；schema1/2仍可读。schema3混入数值元数据、缺失前后身份、同时变更两个标识或上下文摘要冲突均报告不可读并保留原件。历史行的默认文本及 UI Automation 名称仅含时间、文件名和操作，避免嵌套收据值通过 WPF 记录对象默认文本泄露。

VMX 备份仅恢复配置，不恢复磁盘、Windows 激活、应用绑定或有效客户机网络身份。
