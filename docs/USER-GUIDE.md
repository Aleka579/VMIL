# 使用指南

当前源码为v0.2.0-alpha.1开发版；实际App应用/历史重开/恢复及最新5de包客户机已验收，既有Alpha包保留原只读范围。配置仅批准登记版本17.5.2.23775571、hardware19、每插槽2核及4096↔6144MiB、2↔4vCPU；远程CI和私密安全渠道仍待完成，尚未正式发布。见[本轮测试](V02-FULL-TEST-RESULTS-2026-10-17.md)与[发布就绪表](../RELEASE-READINESS.md)。

## 启动

解压完整 Windows x64 包，运行 VMIdentityLab.App.exe。保留同目录全部文件。自包含包带运行时，普通用户无需安装开发SDK或系统.NET；已在声明的Win10教育版18363目标按该范围验证，见[本轮结果](READINESS-TEST-RESULTS-2026-10-11.md)。

## 五个页面

1. 概览：点击“开始检测”，查看系统、证据状态和字段可用性。
2. 检测详情：查看五类观测及来源；不可用、超时和失败与成功分开。
3. VMX 配置：点击“选择 VMX”查看声明与支持依据，初始电源为未知；可连接本机API只读查询，或按下述有限范围预览并确认配置操作。
4. 报告对比：本机报告作为 A；导入客户机报告 B，查看相同、不同和不可比较字段。也可导入另一份 A。
5. 报告导出：保存脱敏 JSON 或静态 HTML；替换已有文件前明确确认。

左下角切换简体中文/English。采集过程中可取消，已有报告保留。

## v0.2 候选预览

在新版VMX页选择文件后，填写拟用内存（MiB）与vCPU数量，点击“预览差异”。页面显示修改前后及影响；悬停差异行可查看完整说明。编辑输入会废弃旧预览，生成预览时重新读取所选文件，不写入它。

点击“审阅变更”查看目标、差异和影响；只有满足精确版本、拓扑和值范围的预览才能确认。核对并勾选同意后，点击应用/恢复，再在“连接本机 VMware API”窗口填写API专用账号，点击“连接并执行已确认配置”。后端重新检查完全关机、唯一目标、实际占用和当前内容，先备份，经官方API更新并完整复核；程序不自动关机，也不直接替换VMX。

展开“备份与恢复历史”刷新当前配置记录，选择备份后生成恢复预览；恢复仅反向修改收据中的参数，保留其他内容。历史路径仅本地显示，不进入公开报告。历史保存失败只能单独重试保存，不能重复应用；参数或拓扑后续变化会拒绝恢复。配置备份不是整机备份。

候选输入规则不代表正式支持范围；拓扑缺失、未知语法或歧义不能获得写入权限。真实副本与写入仍须具体方案确认；CLI只读，旧v0.1包没有新增界面。

若看到“API操作结果尚未确认”，保留备份、预期配置和操作记录；不要删除pending或直接重试。超时不代表服务端没有修改，须先核实服务端操作结束及实际配置。当前没有自动核销未决记录功能。明确拒绝也先验证原设置/内容未变，归档后仍须新的预览与确认；不自动重发。旧Alpha快照不包含最新后端，来源以BUILD-INFO为准。

## 查询本机VMware电源状态

该功能可选；检测系统信息和读取VMX不需要API账号。先按VMware官方工具的说明配置vmrest专用账号，并确认接口仅在回环地址监听；账号配置会保存到VMware管理的位置。本轮使用普通用户权限，软件不会自动创建账号、启动接口或改变VM电源。

选择VMX后点击“读取电源状态”，在本机窗口填写端口（默认8697）与专用API账号，点击“连接并查询”。这不是Windows或客户机登录账号。App仅在本次请求中使用凭据，不将它们保存到程序设置或报告；每次查询需要重新输入。

查询先核对VMX与注册ID，之后读取运行、挂起或完全关机状态。未连接、认证失败、接口不可用、注册歧义、暂停或无法识别的响应显示“未知”。这是查询时刻的快照；状态变化后重新查询。CLI未配置此连接，仍保持未知。Workstation17.5.2实测与其他版本限制见[依据表](VMWARE-17.5.2-EVIDENCE.md)。

## 客户机采集与传回

客户机允许Windows 10/11 x64，记录实际版本/Build并验证兼容；VMware最低17.5.2。完整版本见[依赖清单](DEPENDENCIES.md)。自包含程序不需要Python或开发SDK；Python>=3.14仅用于单独的MCP测试工具。运行及电源动作按授权处理。将完整包复制到客户机，打开其所在目录，执行：

```powershell
.\VMIdentityLab.App.exe --collect --output .\guest-report.json --html .\guest-report.html
```

将 guest-report.json 手动传回宿主机，再导入为报告B。Win10教育版18363普通权限采集、GUI导出及真实宿主/客户机报告交换已通过，见[客户机结果](GUEST-TEST-RESULTS-2026-10-11.md)。

采集模式复用 GUI 引擎；输出文件存在时拒绝覆盖。GUI 支持显式确认覆盖。程序不建立客户机后台服务或自动传输。

## 结果解释

Hypervisor 信号可能来自宿主虚拟化功能；Tools 和 VMware 设备痕迹也可能出现在宿主机。多来源一致才显示一致证据，缺失结果与证据不足显示未知/不足，不保证设备身份。

VMX 中的 guestOS、内存与 vCPU 是配置声明；实际 OS Build、内存与设备信息来自客户机采集。默认报告不包含完整 VMX、个人路径、序列号、UUID 或 MAC。

## 当前限制

- v0.1不修改配置；v0.2实际应用/历史/恢复仅在上述精确范围验收，其他范围拒绝。App租约不锁住第三方操作；提交期间遇到状态/内容变化会保留未决证据并停止，不自动重放或整份回滚。
- 本机17.5.2电源状态和现有Win10客户机无需SDK/系统.NET的运行范围已验证；其他具体OS/VMware版本和全新系统环境未测试。MCP测试的客户机空密码认证不受支持。
- 宿主检测/取消/文件选择/导入/对比/导出/中英文切换已由自动驱动实际验证，详见[宿主结果](HOST-TEST-RESULTS-2026-10-11.md)。
- 原0.1.0-alpha.1 ZIP含旧GBK解析问题；当前alpha.2源码及2026-10-11完整验证包包含修复与状态查询。历史验证包没有追改版本，新版也尚未正式发布。编码或内容无法解析时会显示明确提示。
- 若发生 Defender 拦截，停止对应操作并保留告警；项目既有受限脚本继续禁止运行。
