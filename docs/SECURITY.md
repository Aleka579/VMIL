# 安全设计

状态：v0.2有限官方API配置及真实App应用/备份/历史重开/恢复已验收，127单元/100模拟集成及最新客户机检查通过；精确范围见[配置政策](VMWARE-CONFIG-POLICY.md)。远程CI与私密安全渠道仍待完成，见[当前结果](V02-FULL-TEST-RESULTS-2026-10-17.md)，历史证据保留原范围。

## 资产与输入

保护用户真实 VMX、虚拟磁盘/快照、硬件标识符、用户路径、凭据和后续外部配置修改。Windows 采集值、VMX、JSON 报告与错误消息都按不可信输入处理。

## 只读采集与隐私

- 默认普通权限；分项记录拒绝访问、超时或接口不可用，不整体自动提权。
- 无遥测、默认本地处理，不建立后台网络上传或长期客户机服务。
- 输出使用字段白名单和类型明确脱敏，覆盖日志、异常、未知 VMX 值和导出。
- 原始信息不进入公开样例和提交；测试数据用合成来源。

## 导入与 HTML

只解析受支持格式；不执行导入数据中的命令、脚本或链接。限制与错误行为实际测试。HTML 字符串正确编码，保持静态；恶意标记不能作为可执行内容输出。

## 配置完整性

v0.1不写VMX。v0.2核实版本、白名单、可靠关机、路径、占用和原内容；明确确认后重新检查。原字节备份与预期文件验证后，仅经官方API更新本次参数并复核，不回落直接替换VMX。恢复以最新内容为基准，只反向修改收据参数，保留其他启动后内容，候选或拓扑有后续变化则拒绝。

同目标持久租约只约束App实例；请求前持久化intent，结果未确认保留pending/备份并阻止新实例重放，不自动回滚或核销。真实provider运行/挂起拒绝和一次启动竞争已测，但不能据此保证所有第三方并发时序。

真实副本核实完整磁盘/快照链引用。只有 VMX 副本、资源仍指原 VM 时禁止写入测试。

恢复历史仅保存在当前用户的LocalApplicationData/VMIdentityLab/configuration-history，不进入诊断JSON/HTML或发布包。记录包含恢复所需的本机配置/备份路径与哈希，不作为可信命令执行；解析限制格式/大小，损坏或中断记录保留并提示。恢复仍重新检查目标、备份/当前哈希和允许变更。配置已应用而历史保存失败时保留收据和备份路径，阻止再应用；只允许重试保存历史，不自动回滚或覆盖外部修改。

## 授权边界

系统级安装、宿主机安全设置、真实 VM 配置/电源/快照、完整副本创建、既有数据覆盖和远程发布先取得用户确认。项目内普通实现与模拟测试在授权范围内继续，不因假设风险重复询问。

## 发布

阶段0与发布时按[依赖清单](DEPENDENCIES.md)核查版本及维护状态。宿主OS、允许的Windows 10/11客户机和用户指定VMware>=17.5.2按明确例外进行兼容测试，官方支持另列；其他SDK/脚本工具/依赖/CI临期或结束支持版本不作为新采用方案。测试成功不改变上游支持状态。

检查源码、暂存范围、日志、报告样例和发布包；真实 VMX/磁盘/备份不提交。不附带 VMware 程序或 Windows 镜像。许可权利人、第三方许可和漏洞报告渠道发布前确认。

公开安全政策见[SECURITY.md](../SECURITY.md)，渠道实际状态与待确认步骤见[GitHub接入](GITHUB-READINESS-2026-10-17.md)，配置规则见[VMWARE-CONFIG-POLICY.md](VMWARE-CONFIG-POLICY.md)。
