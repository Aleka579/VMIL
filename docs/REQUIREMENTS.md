# 需求与验收映射

状态：按 [模块顺序](MODULES.md) 开发，基础工程和报告模块已有实际构建/测试结果；完整验收见 PROGRESS.md。阶段 0–4 为 v0.1（25 条），阶段 5 为 v0.2（6 条），阶段 6 为发布验收（6 条），共 37 条。

## 功能需求

- R-01：检测 Windows 虚拟化特征，提供可核实证据。
- R-02：只读查看 VMX 与运行状态，保留未知内容。
- R-03：宿主机与客户机分别采集，导入后比较。
- R-04：导出默认脱敏 JSON/HTML，支持普通权限操作。
- R-05：WPF/MVVM 基本界面、后台操作、中文与英文资源。
- R-06：版本明确的少量配置白名单、预览、确认、备份和恢复。
- R-07：测试、兼容性、许可、CI 和开源交付有实际证据。

## 使用与边界需求

- 宿主OS不设门槛；客户机/干净目标允许Windows 10/11 x64，按具体版本/Build实测。VMware Workstation Pro最低17.5.2，MCP工具Python最低3.14；其他工具要求见[依赖清单](DEPENDENCIES.md)。
- 上述用户指定环境是原维护期门槛的例外；其他SDK、脚本工具、依赖和CI仍核查维护期，临期版本不作为新采用方案。官方支持与项目实测分列。
- 访问入口、具体Build或能力缺失时记录实际阻塞；环境创建、升级和系统安装仍先确认，不把规则变化写成验收通过。

- 默认只读、无遥测，不把虚拟化分析作为第三方检测规避功能。
- 硬件接口失败或权限不足正常降级，未知不等于未检测到。
- 真实配置写入前可靠确认完全关机；挂起、未知和运行中均拒绝。
- 真实写入测试使用完整独立副本，磁盘/快照链不得指向原 VM。
- 备份恢复范围仅 VMX；恢复不得覆盖用户后续外部修改。
- 数据导出、日志、公开样例和仓库按隐私规则处理。
- 未执行测试、未经确认的许可和未运行的 CI 均不能标通过。

## 状态与变更

验收状态在 [PROGRESS.md](../tasks/PROGRESS.md) 和对应阶段文件同步维护。每条完成需对应实际结果。修改要求时先说明用户目标、理由和影响，再同步本文件、阶段任务、测试矩阵和发布就绪表；不为获得绿色状态降低要求。

## 发布判定

v0.1 不要求 CFG 项完成；v0.2 需要目标配置的真实副本证据。REL 项用于发布范围，不等于远程推送已获授权。远程 CI 尚无授权时列为未验证，并先交付可审查的本地成果。
