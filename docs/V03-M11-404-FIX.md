## 原因

研究工具使用了随附 Swagger 声明的 `PUT /api/vms/{id}/configparams`，但精确 vmrest 构建实际注册的是 **`PUT /api/vms/{id}/params`**。工具沿用了错误路径；原 name/value 请求体和媒体类型正确。

本次只读检查 PE32 路由注册、Go 函数和请求结构元数据，没有启动或修改 VMware。vmrest 为已核实的 `1.3.1 build-23775571`，SHA256 `72afedfc0403a5e21ec44c9176241096077d74f6d0fc8e8e862bfd8b6ee57646`；Workstation 为 `17.5.2 build-23775571`。

| 证据 | 已核实事实 |
| --- | --- |
| `swagger.zip/json/swagger_WS.json`，SHA256 `71c8094a4ab765151111ac4fd68a2bf8ace1061d470ef4ac2c5dc6f86aebb3f7` | basePath `/api`，声明 PUT `/vms/{id}/configparams`；body 是 name/value 字符串，媒体类型 `application/vnd.vmware.vmw.rest-v1+json` |
| `main.registerApiWebServerHandler` 的同一注册块 | 更新处理器 `rest.(*RestServer).UpdateConfigParamsHandler-fm`，PUT，路径 `/api/vms/{id}/params`，长度20 |
| 固定映像静态位置 | 路径 VA `0x7d1ddd`、引用文件偏移2928349；PUT 字符串 VA `0x7cb98b`；处理器包装函数 VA `0x6d0550`。用于该固定 PE 的静态复核，不保证运行时地址 |
| 更新处理器 JSON 结构 | `Name` 标签 `json:"name"`，`Value` 标签 `json:"value"`，两者为字符串 |
| 旧路径 | 映像没有 `/configparams` 字符串；注册块明确使用 `/params`，结论不只依靠字符串缺失 |

[上一轮 UUID PUT 404](V03-M11-REAL-API-RESULTS.md)与此缺陷一致。MAC 当时未记录请求资源，不能补造旧捕获；代码也会使用相同错误路径，但推断不改写成旧日志事实。

这是精确程序行为证据，**不是新的官方逐字段保证或生产准入**。在线[官方索引](https://developer.broadcom.com/xapis/vmware-workstation-pro-api/latest/operation-index/)仍标1.2.1，不能替代本构建核实；实际字段往返仍需复验。

## 修复

- 研究工具固定使用 `/params`。原版本/契约/二进制/监听映像绑定保持；不猜测路由，不在404后自动切换或重试。
- 错误正文最多读取4097字节，只输出受限分类及整数错误码，不保留 message、VM ID、路径或凭据。标准404正文特征与 JSON ErrorModel 分开；正文特征不独立证明路由缺失。
- 错误记录字段、正向/恢复及 `before-intent`、`before-put`、`put`、`readback` 阶段。只有PUT的4xx且独立证明请求前完整状态未变，才记录 `rejected-unchanged`；其余不明结果保留 intent。
- 修正 FakeApi 对错误路由的接受，新增严格 HTTP 服务器验证实际路径、JSON和媒体类型。服务器仅运行于本机临时端口，不连接 VMware。

生产 C# 后端、M07策略、M10不可执行计划、版本及依赖未变。研究工具不随 App 发布。
