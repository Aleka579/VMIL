测试在发现字节差异后停止并保全，完成解释后才继续评审。一次竞争只观察到 PUT 先完成的顺序，不代表所有线程时序已穷举。生产后端仍要求提交后完全关机、参数及全文件哈希符合预览；若遇到这种启动竞争，即使 API 暂时仍报 off，也必须保留 pending/备份并停止，不能重放或整份回写。相应合成故障回归已通过，见下文。

## 本轮有限源码策略

官方依据为 [Update VM](https://developer.broadcom.com/xapis/vmware-workstation-pro-api/latest/api/vms/id/put/) 的 memory/processors 字段及409状态冲突；本地随安装资料与本轮17.5.2实测共同限定适用范围，latest说明不外推为所有版本的保证。官方接口没有声明CAS或全局文件锁。

| 参数 | 唯一批准版本/拓扑 | 允许前后值 | 影响与恢复 |
| --- | --- | --- | --- |
| API memory / VMX memsize | Workstation17.5.2 build23775571、hardware19、每插槽2核 | 4096↔6144 MiB | 改变客户机可用内存；完全关机后以新预览经API反向修改参数 |
| API processors / VMX numvcpus | 同上 | 2↔4 | 改变逻辑CPU及厂商派生元数据；保持每插槽2核，恢复只改收据参数 |

其他版本、原值/目标值、hardware版本或拓扑保持拒绝。未知、运行、挂起、实际占用、歧义、加密、已有未决结果均不能写入。白名单只批准API字段，旧文件写入策略保持关闭；没有测试策略或环境变量放行入口。
